# asahikawa-bus-departure

旭川市内のバス発車案内を表示する Web アプリケーション。GTFS データをもとに、登録した経路の発車時刻・運賃・地図を確認できる。

## 📋 概要

旭川電気軌道・道北バス・ふらのバスの 3 事業者に対応した発車案内ツール。乗車バス停と降車バス停を登録すると、直近の発車時刻を一覧表示する。

データはすべてブラウザ内で処理される。サーバーへの送信は行わない。登録した経路は IndexedDB に保存され、ブラウザを閉じても維持される。

## 🔧 主な機能

### 発車案内

登録経路の発車時刻を 1 分間隔で自動更新する。出発目安時刻（徒歩時間を差し引いた自宅出発時刻）、運賃、路線名、行き先を表示する。出発済みの便には「出発済」バッジ、翌日の始発以降の便には「始発以降」バッジが付く。

### 行先フィルタ

複数の行先がある場合、タグ形式のボタンで絞り込める。複数の行先を同時に選択でき、一覧と地図が連動してフィルタされる。

### 経路マップ

Leaflet + OpenStreetMap で経路の形状を地図上に描画する。タイルにセピアフィルタを適用し、テーマに応じた配色で表示する。一覧の行にホバーすると対応する経路がハイライトされる。クリックでハイライトを固定でき、一覧表と地図が連動する。通常スクロールでは地図をズームせず、Ctrl/Cmd + スクロールでのみズームする。

### 経路登録

バス停名のインクリメンタルサーチで乗車・降車バス停を選択する。検索結果には事業者カラーバッジが表示され、複数事業者が乗り入れるバス停では全事業者のバッジが並ぶ。名前に包含関係があり 200m 以内のバス停は自動統合される（例: 「旭川駅/旭川駅前」）。徒歩時間はデフォルト 10 分で、出発目安の算出に使われる。経路ごとに通知のオン/オフを設定できる。

一方のバス停を選択すると、もう一方の候補は「乗り換えなしで到達できるバス停」に自動で絞り込まれる。入力した名称が候補に出ない場合は「乗り換えなしで到達できない組み合わせ」の可能性を入力欄付近で告知する。登録ボタン押下時のバリデーションは、未選択・存在しない名称・候補から未選択・乗り換えなしで到達不可能をそれぞれ区別してエラーメッセージで示す。登録・更新が完了すると成功トーストで通知する。

### エクスポート / インポート

登録経路を JSON ファイルで書き出し・読み込みできる。端末間の移行やバックアップに利用する。ヘッダーのボタンから操作する。

### テーマ切り替え

ライト・ダーク・デバイス設定の 3 種類から選択できる。ヘッダーのセレクトボックスで切り替える。地図タイルのフィルタもテーマに連動する。

### 通知

経路ごとに通知のオン/オフを設定できる。通知が有効な経路の発車 N 分前（デフォルト 5 分）にブラウザ通知を送る。通知タイミングはヘッダーからグローバルに設定可能。タブが開いている間のみ動作する（Web Notifications API を使用）。

### 免責表示とデータ出典

ページ上部に免責表示と各事業者の公式サイトへのリンクを表示する。交通データの出典（HODA）と CC BY 4.0 ライセンスも明記している。

## 📖 使い方

### 1. 経路を登録する

画面下部の「経路登録」セクションで乗車バス停と降車バス停を検索・選択する。徒歩時間（分、デフォルト 10）を入力し、必要に応じて通知をオンにして「登録」を押す。

### 2. 発車案内を確認する

登録した経路の発車時刻が一覧に表示される。複数の行先がある場合はタグをクリックして絞り込める（複数選択可）。1 分ごとに自動更新される。

### 3. 地図で経路を確認する

一覧の上に経路マップが表示される。行の上にカーソルを置くと、対応する経路がハイライトされる。行をクリックするとハイライトが固定され、再クリックで解除される。

### 4. 経路をバックアップする

ヘッダーのエクスポート・インポートボタンから経路データの書き出し・読み込みができる。JSON 形式で保存される。

## 💻 開発

### 前提条件

- Node.js 22 以上
- npm

### セットアップ

```bash
npm install
```

### 開発サーバー

```bash
npm run dev
```

Vite の HMR が有効な開発サーバーが起動する。

### テスト

```bash
npm test          # 全テストを 1 回実行
npm run test:watch # ファイル変更を監視して自動実行
```

### ビルド

```bash
npm run build
```

TypeScript の型チェックと Vite のプロダクションビルドを実行する。成果物は `dist/` に出力される。

### リント・フォーマット

```bash
npm run check     # 問題の検出
npm run check:fix # 自動修正
```

Biome によるリントとフォーマットを実行する。

## 🔄 データ更新

GTFS データは GitHub Actions で自動更新される。

| ワークフロー | 頻度 | 内容 |
|-------------|------|------|
| `update-gtfs.yml` | 毎週月曜 3:00 UTC | HODA から GTFS データをダウンロードし JSON に変換。更新があれば自動デプロイ |
| `update-osm.yml` | 毎月 1 日 2:00 UTC | Geofabrik から北海道の OSM データを取得し pfaedle で経路形状を生成 |

データソースは [HODA（北海道オープンデータプラットフォーム）](https://ckan.hoda.jp)の [公共交通GTFSデータ](https://ckan.hoda.jp/dataset/gtfs-data)を使用している（[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/deed.ja)）。

### 複数期間データの保持

HODA がダイヤ改正時に次期データで上書きすると、現行ダイヤのデータが失われる場合がある。これを防ぐため、最新の GTFS データに加えて一期間前のデータをキャッシュで保持する。カレンダーの `start_date` が変化した場合のみデータを更新し、ダイヤ開始日が今日以前のデータを優先して表示する。
