## 🔎 発端

[Issue #126][i126] は「Biome の整形ドリフトが CI で検知されていない」と書いていた．`npm run check:fix` が 10 ファイルを書き換える状態であり，CI に Biome のジョブが無いためずれが通る．そういう筋書きだった．

着手時に測り直すと 11 ファイルへ増えていた．`scripts/convert-gtfs.ts` が新たに加わっている．ずれは止まらず広がっていた．

## 🕳 二段目の問題

`deploy.yml` のトリガを確かめたところ，次のようになっていた．

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

Pull Request では動かない．PR に掛かる workflow は `md-lint.yml` だけであった．

つまり欠けていたのは Biome ではない．**`npm test` すら PR では走っていなかった**．テストの失敗も型エラーも，マージされて main へ入るまで表に出ない．

チェック欄は緑に見える．走っていたのは Markdown lint だけである．前回の調査で得た「緑のジョブを正常の証拠として扱わない」が，別の形で再び当てはまった．経緯は [OSM キャッシュの退避と pfaedle の無言スキップ](2026-09-01-osm-cache-eviction.md) を参照．

## 🛠 検査の担当分け

Biome のジョブを `deploy.yml` へ足しても，PR は素通しのままになる．そのため PR 用の `ci.yml` を新設した．

最初は `pull_request` と `push: main` の両方で動かした．セルフレビューがこれを捕まえた．main への push では `deploy.yml` がテストとビルドを走らせるため，同じ検査が二重に実行される．

表 1. 検査の担当

| workflow | トリガ | 担当 |
|---|---|---|
| `ci.yml` | Pull Request | 整形・lint・テスト・ビルド |
| `deploy.yml` | main への push | 同じ検査ののちデプロイ |

`ci.yml` を Pull Request 限定とし，`deploy.yml` へ `npm run check` を足した．どちらの経路でも同じ検査を通り，重複は生じない．

### 代替案と棄却理由

- **`ci.yml` を両方のトリガで動かす**: テストとビルドが二重に走る．Actions の時間を無駄に消費する．
- **`deploy.yml` から検査を外す**: 公開直前の関門が消える．デプロイの経路は自己完結させたい．
- **Biome のジョブだけ足す**: 元の Issue が求めた形だが，PR でテストが走らない欠陥を残す．

## ♿ リンタの提案をそのまま当てない

残った lint の指摘 4 件のうち，2 件がアクセシビリティに関わっていた．

`noNoninteractiveTabindex` は，並び替え可能な列見出しに付いていた．`th` へ `tabIndex` を与え，`onKeyDown` で Enter と Space を自作していた．

Biome の unsafe fix は「`tabIndex` を消す」である．**これを当てるとキーボードで並び替えを操作できなくなる**．指摘は正しいが，提案は解決になっていない．

採ったのは WAI-ARIA Authoring Practices の形である．`th` の中へボタンを置き，操作をボタンへ移した．Enter と Space の扱いはボタンの既定の挙動が担うため，自作の分岐を消せる．`aria-sort` は列の状態であるため `th` に残した．

クリックできる範囲が狭まらないよう，ボタンへ `w-full` を与えた．`th` の padding には反応しなくなるが，文字だけの的よりは広い．

`useSemanticElements` は `role="group"` を置いた `div` を `fieldset` へ改めた．

## 🧪 構造を変える前に振る舞いを固定する

DOM の形を変えると，既存のテストが壊れる．3 箇所が `th` を直接クリックしていた．

先に，操作対象を関数で受け取るテストを足した．見出し自体でも内側のボタンでも通る形である．あわせて Enter と Space で並び替えが切り替わることを検証した．

このテストは変更前の実装でも通る．構造を変えても振る舞いが保たれることを，実装コミットの前後で同じテストが保証する．

セルフレビューは，実装が確定したあとの抽象を指摘した．見出し自体へ落ちる分岐は到達しない経路であり，読み手を惑わせる．リファクタが済んだら畳むのが正しい．**移行のための抽象は，移行が終われば負債になる**．

## 🕵 レビューの指摘も実測で確かめる

セルフレビューは `fieldset` への置き換えを重要度 medium で指摘した．根拠は「Tailwind の preflight に `fieldset` のセレクタが無いため，既定の枠線と余白が残る」であった．

実際には残らない．preflight の冒頭に次の指定がある．

```css
*, ::after, ::before, ::backdrop, ::file-selector-button {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
  border: 0 solid;
}
```

ブラウザで実測したところ，`fieldset` と `div` の `border`・`padding`・`margin` はいずれも 0px で一致した．違いは `min-inline-size: min-content` だけであり，`min-w-0` で打ち消した．

要素名でセレクタを探すと，全称セレクタによるリセットを見落とす．**指摘の妥当性は，読みではなく測定で判断する**．

## 🪤 作業中に踏んだ落とし穴

### 開発サーバーで wasm が配信されない

UI の変更を実機で見ようとした．`npm run dev` を起動したところ，アプリがデータを読み込めない．`/sql-wasm.wasm` と `/sql-wasm-browser.wasm` だけが `index.html` を返していた．

同じ内容を別名でコピーすると正しく配信される．ファイル名に依存した挙動であり，`sql.js` の依存最適化との干渉が疑わしい．本番ビルドでは再現しない．[Issue #132][i132] で追う．

### MSYS のパス変換で `--base=/` が化ける

本番ビルドで確認する回り道を選んだが，今度は真っ白なページが出た．読み込むスクリプトの URL は次のようになっていた．

```text
http://localhost:4174/Program%20Files/Git/assets/index-DC6q29Io.js
```

Git Bash 経由の `--base=/` が Windows のパスへ書き換わっていた．ビルドは成功する．失敗するのは表示だけである．PowerShell で実行し直して解決した．

**成功した表示と壊れた出力は両立する**．引数の中身は成果物の側から確かめる．

### reviewdog の件数表示

lint summary は「この PR の差分 42 件」と出した．追加した行にはほとんど心当たりがない．

内訳を見ると，変更したファイル全体の件数であった．追加行に掛かる指摘は inline コメントとして付き，そちらは 1 件だった．修正後は 42 件から 41 件へ減っている．

reviewdog は非ブロッキングであり CI を落とさない．件数の読み方を知らないと，緑のまま見過ごすか，範囲外の是正へ引きずられる．

## 💡 一般化できる教訓

- **Issue の主語より広く測る**: 起票は「Biome のジョブが無い」だった．検査の欄そのものを見ると，テストも走っていなかった．
- **リンタの提案は解決ではない**: `tabIndex` の削除はキーボード操作を壊す．指摘の正しさと提案の正しさは別である．
- **移行のための抽象は移行後に畳む**: 双方の DOM 構造を許す関数は，構造が確定した時点で片方が死ぬ．
- **指摘は測定で検証する**: 全称セレクタによるリセットは，要素名を探しても見つからない．
- **ビルドの成功は表示の正しさを意味しない**: 引数が化けても終了コードは 0 になる．
